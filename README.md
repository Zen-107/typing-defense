# Typing Defense

เกมฝึกพิมพ์บนเบราว์เซอร์ คำศัพท์จะร่วงลงมาจากด้านบนของจอ ผู้เล่นต้องพิมพ์คำนั้นให้ครบก่อนที่มันจะตกถึงพื้น ถ้าปล่อยให้คำตกถึงพื้นจะเสียหัวใจ 1 ดวง มีทั้งหมด 3 ดวง และเกมจะยากขึ้นทุก ๆ 30 วินาที

โปรเจกต์นี้ทำขึ้นเพื่อการเรียนรู้ 2 เรื่องไปพร้อมกัน:

1. **การเขียนเกมด้วย JavaScript ล้วน ๆ** ไม่ใช้ framework ไม่มี build step และแยก "กติกาของเกม" ออกจาก "ส่วนที่วาดบนจอ" ทำให้เขียน unit test ได้ทุกกติกา
2. **การทำงานแบบทีมด้วย AI agent** โปรเจกต์ทั้งหมดถูกสร้างโดย Claude Code subagent 5 ตัว ที่สวมบทบาท Product Owner, Architect, QA, Developer และ Reviewer โดยมีมนุษย์คอยตัดสินใจในจุดสำคัญ (ดูหัวข้อ [11](#11-โปรเจกต์นี้ถูกสร้างขึ้นอย่างไร-ทีม-ai-agent))

**วิธีที่ 2: ใช้ VS Code Live Server**

> **ทำไมดับเบิลคลิกเปิด `index.html` ตรง ๆ ไม่ได้?**
> โค้ดใช้ ES modules (`import` / `export`) ซึ่งเบราว์เซอร์ยอมโหลดผ่าน `http://` เท่านั้น ไม่ยอมโหลดผ่าน `file://` ด้วยเหตุผลด้านความปลอดภัย จึงต้องเปิดผ่าน web server เสมอ

### รันเทส

```bash

```

ซึ่งจะไปรันคำสั่งนี้:


ผลที่ควรได้คือ `tests 245`, `pass 245`, `fail 0`

> **ข้อควรระวัง:** อย่าใช้ `node --test tests/` (ระบุเป็นโฟลเดอร์) เพราะใน Node 21 ขึ้นไป อาร์กิวเมนต์จะถูกตีความเป็น glob pattern และคำสั่งแบบโฟลเดอร์จะ error บน Node 24 ทีมเจอปัญหานี้จริงระหว่างทำโปรเจกต์ ต้องใส่เครื่องหมายคำพูดครอบ pattern ไว้ด้วย เพื่อให้ Node เป็นคนขยาย `**` เอง ไม่ใช่ shell

## 2. วิธีเล่น

| ปุ่ม | ผล |
|---|---|
| `Enter` | เริ่มเกม / เล่นต่อหลังหยุดชั่วคราว / เล่นใหม่หลัง Game Over |
| `a`–`z` | พิมพ์คำ (พิมพ์ใหญ่หรือเล็กก็ได้ ระบบมองเป็นตัวเดียวกัน) |
| `Backspace` | ลบตัวอักษรที่พิมพ์ไปล่าสุด 1 ตัว ถ้าลบจนหมด จะปลดการเล็งคำนั้น |
| `Escape` | ยกเลิกคำที่กำลังเล็ง เพื่อไปพิมพ์คำอื่น |
| ปุ่มอื่น ๆ (ตัวเลข, เว้นวรรค, ลูกศร) | ไม่มีผลใด ๆ |

**ขั้นตอนการเล่น**

1. กด `Enter` ที่หน้าแรก คำแรกจะปรากฏทันที
2. พิมพ์ตัวอักษรแรกของคำที่อยากยิง เกมจะ "เล็ง" คำนั้น (คำจะเปลี่ยนเป็นสีเหลืองและมีขีดเส้นใต้)
3. พิมพ์ต่อให้ครบ ตัวที่พิมพ์ถูกแล้วจะเป็นสีเขียว พอครบทั้งคำ คำจะหายไปและได้คะแนน
4. ถ้าคำไหนตกถึงพื้น จะเสียหัวใจ 1 ดวงและขอบจอจะกะพริบสีแดง
5. หัวใจหมดคือ Game Over หน้าสรุปผลจะแสดงคะแนน เลเวล จำนวนคำที่ยิงได้ และความแม่นยำ

**เกมหยุดเองอัตโนมัติ** ถ้าสลับแท็บหรือสลับไปหน้าต่างอื่น และจะเล่นต่อเมื่อกด `Enter` เท่านั้น (กลับมาที่แท็บเฉย ๆ เกมจะยังไม่เดิน)

## 3. กติกาและตัวเลขทั้งหมด

กติกาทุกข้อถูกกำหนดเป็นตัวเลขที่ชัดเจน เพื่อให้เขียนเทสได้ ค่าคงที่ทั้งหมดอยู่ใน `CONFIG` ใน [src/game-logic.js](src/game-logic.js)

### 3.1 ค่าพื้นฐาน

| ค่า | ตัวเลข |
|---|---|
| ขนาดสนามเล่น (หน่วย logical) | 800 × 600 px |
| หัวใจเริ่มต้น | 3 (เพิ่มไม่ได้) |
| คำบนจอพร้อมกันได้มากสุด | 10 คำ |
| คำถือว่า "ตก" เมื่อ | y ≥ 600 |
| ระยะห่างจากขอบซ้าย-ขวา | อย่างน้อย 10 px |
| เวลาต่อเฟรมสูงสุดที่นำไปคำนวณ (dt cap) | 100 ms |
| เลเวลเพิ่มทุก ๆ | 30 วินาที (เวลาในเกม) |
| เลเวลสูงสุด | 10 (ถึงที่วินาทีที่ 270) |
| หน้า Game Over ไม่รับ `Enter` ช่วงแรก | 500 ms |

### 3.2 ความยากตามเลเวล

| เลเวล | เริ่มที่ (วินาที) | คำใหม่ทุก ๆ (ms) | ความเร็วตก (px/s) | เวลาตกจนถึงพื้น (วินาที) | ความยาวคำ (ตัวอักษร) |
|---|---|---|---|---|---|
| 1 | 0 | 2000 | 40 | 15.0 | 3–4 |
| 2 | 30 | 1850 | 50 | 12.0 | 3–4 |
| 3 | 60 | 1700 | 60 | 10.0 | 3–5 |
| 4 | 90 | 1550 | 70 | 8.6 | 3–5 |
| 5 | 120 | 1400 | 80 | 7.5 | 4–6 |
| 6 | 150 | 1250 | 90 | 6.7 | 4–6 |
| 7 | 180 | 1100 | 100 | 6.0 | 4–7 |
| 8 | 210 | 950 | 110 | 5.5 | 5–7 |
| 9 | 240 | 800 | 120 | 5.0 | 5–8 |
| 10 | 270 | 650 | 130 | 4.6 | 5–8 |

สูตรที่ใช้สร้างตารางนี้:

```js
level      = min(10, 1 + floor(elapsedSec / 30))
interval   = max(650, 2000 - 150 * (level - 1))   // ms
fallSpeed  = min(130, 40 + 10 * (level - 1))      // px/s
```

> เวลาตกจนถึงพื้น = 600 ÷ ความเร็ว เช่นที่เลเวล 1 คือ 600 ÷ 40 = 15 วินาที

เมื่อเลเวลเพิ่ม **คำที่อยู่บนจออยู่แล้วก็ตกเร็วขึ้นด้วย** และจะมีข้อความ "Level N" แสดงกลางจอ 1 วินาที

### 3.3 คะแนน

```
คะแนนต่อคำ = 10 × ความยาวคำ × เลเวลตอนที่ยิงคำนั้น
```

ตัวอย่าง: "cat" ที่เลเวล 1 = 30 คะแนน, "planet" ที่เลเวล 4 = 240 คะแนน, "keyboard" ที่เลเวล 10 = 800 คะแนน

พิมพ์ผิดหรือปล่อยคำตก **ไม่หักคะแนน** ไม่มีคอมโบหรือโบนัสใด ๆ

### 3.4 ความแม่นยำ (Accuracy)

```
accuracy = round(ตัวที่พิมพ์ถูก × 100 / (ตัวที่พิมพ์ถูก + ตัวที่พิมพ์ผิด))
```

ปัดเศษ .5 ขึ้นเสมอ (เช่น 57.5% → 58%) ถ้ายังไม่ได้กดอะไรเลยจะแสดง 0%

> สูตรนี้ต้อง **คูณ 100 ก่อนแล้วค่อยหาร** ถ้าหารก่อน จะเกิดบั๊กเรื่องทศนิยม ดูรายละเอียดในหัวข้อ [12](#12-บทเรียนที่ได้จากโปรเจกต์)

### 3.5 การเกิดคำใหม่ (Spawn)

- คำใหม่เกิดที่ y = 0 ส่วนตำแหน่ง x สุ่มให้ทั้งคำอยู่ในสนามโดยห่างขอบอย่างน้อย 10 px
- สุ่มความยาวจากช่วงของเลเวลนั้นก่อน แล้วค่อยสุ่มคำจากคำที่ยาวเท่านั้น
- คำใหม่ **ต้องไม่ซ้ำ** กับคำบนจอ และ **ต้องไม่ขึ้นต้นด้วยตัวอักษรเดียวกับคำที่กำลังเล็งอยู่**
- สุ่มได้สูงสุด 10 ครั้ง ถ้าไม่ผ่านเงื่อนไขทั้ง 10 ครั้ง รอบนั้นจะข้ามไปไม่เกิดคำ
- ถ้ามีคำบนจอครบ 10 คำแล้ว ก็ข้ามรอบนั้นไปเช่นกัน

## 5. สถาปัตยกรรม: ทำไมต้องแยก logic ออกจากการวาด

นี่คือแนวคิดที่สำคัญที่สุดของโปรเจกต์ โค้ดถูกแบ่งเป็น 2 ฝั่ง:

```
┌──────────────────────────── เบราว์เซอร์ ────────────────────────────┐
│                                                                     │
│   คีย์บอร์ด ──┐        เวลาจริง (rAF)      Math.random              │
│   สลับแท็บ ──┤             │                   │                    │
│              ▼             ▼                   ▼                    │
│        ┌───────────────── main.js ─────────────────────┐            │
│        │  รับ event → ส่งต่อให้ logic → เอา state ใหม่ไปวาด │            │
│        └───────┬──────────────────────────────▲────────┘            │
│                │ state, key, dt, rng          │ state ใหม่            │
│                ▼                              │                     │
│        ┌──────────────── game-logic.js ───────┴───────┐             │
│        │  pure functions: ไม่รู้จัก DOM / เวลา / random   │  ◄── เทสได้  │
│        └───────────────────────────────────────────────┘             │
│                                                                     │
│        main.js ── state ──► renderer.js ──► <canvas>                │
└─────────────────────────────────────────────────────────────────────┘
```

### "Pure function" คืออะไร และทำไมสำคัญ

ฟังก์ชันใน `game-logic.js` ทุกตัวทำตามกฎ 4 ข้อ:

1. **ไม่แตะ DOM** ไม่มี `document`, `window`, `canvas`
2. **ไม่อ่านเวลาเอง** ไม่มี `Date.now()` หรือ `performance.now()` เวลาจะถูกส่งเข้ามาเป็นพารามิเตอร์ `dtSec`
3. **ไม่สุ่มเอง** ไม่มี `Math.random()` แต่รับฟังก์ชันสุ่ม `rng` เข้ามาเป็นพารามิเตอร์
4. **ไม่แก้ไขข้อมูลที่รับเข้ามา (immutable)** ทุกฟังก์ชันคืน state ก้อนใหม่เสมอ

ผลลัพธ์คือ: **ใส่ input เดิม ได้ output เดิมทุกครั้ง** จึงเขียนเทสแบบนี้ได้:

```js
// สมมติว่ามีคำ "cat" อยู่ที่ y = 599.9 และเหลือหัวใจ 1 ดวง
const s0 = makeState({ lives: 1, words: [makeWord(1, 'cat', 599.9)] });
const s1 = update(s0, 0.05, noRng(), SMALL_INDEX);   // ผ่านไป 0.05 วินาที

assert.equal(s1.status, 'GAME_OVER');   // แน่นอน 100% ไม่ขึ้นกับดวงหรือความเร็วเครื่อง
```

ถ้า logic เรียก `Math.random()` หรือ `Date.now()` เอง ผลจะเปลี่ยนไปทุกครั้งที่รัน และเทสแบบนี้จะทำไม่ได้เลย

### การ "ฉีด" ความสุ่มเข้าไป (Dependency Injection)

ในเกมจริง `main.js` ส่ง `Math.random` เข้าไป:

```js
const rng = Math.random;
state = update(state, dtSec, rng, wordsByLength);
```

ในเทส เราส่ง rng ปลอมที่คืนค่าตามลำดับที่กำหนดไว้แทน:

```js
const rng = seqRng([0.0, 0.5, 0.25]);   // เรียกครั้งที่ 1 ได้ 0.0, ครั้งที่ 2 ได้ 0.5, ...
```

`seqRng` ใน [tests/fixtures.js](tests/fixtures.js) ยัง **throw error ถ้าถูกเรียกเกินจำนวนที่เตรียมไว้** ทำให้เทสจับได้ทันทีถ้าโค้ดเรียกสุ่มมากกว่าที่ออกแบบไว้ เพราะเหตุนี้ DESIGN.md จึงกำหนด **ลำดับการเรียก rng ใน `trySpawn` ไว้ตายตัว**:

1. ถ้ามีคำครบ 10 คำ → ข้าม (ไม่เรียก rng เลย)
2. สุ่มความยาวคำ (เรียก 1 ครั้ง)
3. สุ่มคำ (เรียก 1 ครั้งต่อการลอง สูงสุด 10 ครั้ง)
4. สุ่มตำแหน่ง x (เรียก 1 ครั้ง)

### main.js: ส่วนเชื่อมกับเบราว์เซอร์

[src/main.js](src/main.js) ยาวแค่ 61 บรรทัด และเป็น **ที่เดียว** ที่เวลาจริงและความสุ่มจริงเข้ามาในเกม หน้าที่ของมันมีแค่:

- ทุกเฟรม: คำนวณ `dt` จาก timestamp ของ `requestAnimationFrame` → เรียก `update` → เรียก `render`
- เมื่อกดปุ่ม: ส่ง `event.key` ให้ `handleKey` และเรียก `preventDefault()` กับปุ่มของเกม (กัน Backspace ไม่ให้ย้อนหน้าเว็บ, กัน Space ไม่ให้เลื่อนจอ)
- ไม่ส่งปุ่มที่กดพร้อม Ctrl/Alt/Cmd ต่อให้เกม เพื่อให้ shortcut ของเบราว์เซอร์ เช่น Ctrl+R ยังใช้ได้
- เมื่อสลับแท็บ (`visibilitychange`) หรือหน้าต่างเสียโฟกัส (`blur`): เรียก `handleFocusLoss`

## 6. State และ State Machine

### 6.1 State object

ข้อมูลทั้งหมดของเกม ณ เวลาหนึ่ง ถูกเก็บไว้ใน object ก้อนเดียว:

```js
{
  status: 'START',        // 'START' | 'PLAYING' | 'PAUSED' | 'GAME_OVER'
  score: 0,
  lives: 3,
  level: 1,
  elapsedSec: 0,          // เวลาในเกม เดินเฉพาะตอน PLAYING
  words: [],              // คำบนจอ: { id, text, x, y }
  nextWordId: 1,          // id เพิ่มขึ้นเรื่อย ๆ → id น้อยกว่า = เกิดก่อน
  targetId: null,         // id ของคำที่กำลังเล็ง
  typed: '',              // ตัวอักษรที่พิมพ์ถูกแล้วของคำที่เล็ง
  wordsDestroyed: 0,
  typos: 0,
  correctKeystrokes: 0,
  spawnTimerMs: 0,        // เหลืออีกกี่ ms จะถึงรอบเกิดคำใหม่
  flashMs: 0,             // เหลืออีกกี่ ms ที่ขอบแดงจะแสดง
  bannerMs: 0,            // เหลืออีกกี่ ms ที่ "Level N" จะแสดง
  gameOverMs: 0,          // อยู่หน้า Game Over มานานเท่าไรแล้ว (ใช้กับกฎ 500 ms)
  skipNextDt: false       // true = เฟรมถัดไปให้ dt = 0
}
```

สังเกตว่า **ตัวจับเวลาทุกตัวเป็นตัวเลขใน state** ไม่ใช่ `setTimeout` ข้อดีคือพอเกมหยุดชั่วคราว ตัวเลขพวกนี้ก็หยุดไปด้วยโดยอัตโนมัติ และเทสก็ตรวจค่าได้ตรง ๆ

### 6.2 State Machine

```
           Enter                       หัวใจหมด (ใน update)
  START ──────────► PLAYING ─────────────────────────────► GAME_OVER
                     │   ▲                                     │
          สลับแท็บ /  │   │ Enter                               │ Enter
          เสียโฟกัส   ▼   │                                     │ (หลังผ่านไป ≥ 500 ms)
                    PAUSED                PLAYING ◄────────────┘
```

| จาก | เหตุการณ์ | ไป | หมายเหตุ |
|---|---|---|---|
| START | Enter | PLAYING | ปุ่มอื่นไม่มีผล |
| PLAYING | หัวใจหมด | GAME_OVER | ในเฟรมเดียวกันเลย และไม่เกิดคำใหม่อีก |
| PLAYING | เสียโฟกัส | PAUSED | เปลี่ยนทันทีใน event handler |
| PAUSED | Enter | PLAYING | เฟรมแรกหลังเล่นต่อใช้ dt = 0 |
| PAUSED | ปุ่มอื่น / ได้โฟกัสคืน | PAUSED | ไม่มีผล |
| GAME_OVER | Enter ก่อน 500 ms | GAME_OVER | กันกรณีกำลังพิมพ์อยู่แล้วเผลอกด Enter ข้ามหน้าสรุปผล |
| GAME_OVER | Enter หลัง 500 ms | PLAYING | เริ่มเกมใหม่ทั้งหมด |

## 7. Game Loop: หนึ่งเฟรมเกิดอะไรขึ้นบ้าง

เบราว์เซอร์เรียกฟังก์ชัน `frame` ประมาณ 60 ครั้งต่อวินาทีผ่าน `requestAnimationFrame`:

```js
function frame(timestamp) {
  const dtSec = lastTimestamp === null ? 0 : (timestamp - lastTimestamp) / 1000;
  lastTimestamp = timestamp;
  state = update(state, dtSec, rng, wordsByLength);
  renderer.render(state);
  requestAnimationFrame(frame);
}
```

### ทำไมต้องใช้ `dt` (delta time)

ถ้าเขียนว่า "ทุกเฟรม ให้คำเลื่อนลง 1 px" จอ 144 Hz จะทำให้คำตกเร็วกว่าจอ 60 Hz ถึง 2.4 เท่า เกมนี้จึงใช้

```js
y += speed * dt      // speed หน่วย px/วินาที, dt หน่วยวินาที
```

ไม่ว่าจอจะเร็วแค่ไหน ที่เลเวล 1 คำจะใช้เวลา 15 วินาทีพอดีจึงจะตกถึงพื้น (มีเทสตรวจทั้งที่ 30 fps และ 144 fps)

### ลำดับการทำงานใน `update()` ตอน PLAYING

ลำดับนี้ถูกกำหนดไว้ใน DESIGN.md และ **สลับลำดับไม่ได้** เพราะเทสถูกเขียนตามลำดับนี้:

1. **คำนวณ dt** ถ้า `skipNextDt` เป็น true ให้ dt = 0 ไม่อย่างนั้นใช้ `clampDt(dtSec)` ซึ่งจำกัดไม่เกิน 0.1 วินาที
2. **ลดตัวจับเวลา** `flashMs` และ `bannerMs`
3. **เพิ่มเวลาและเช็กเลเวล** ถ้าเลเวลเพิ่ม ให้ตั้ง `bannerMs = 1000`
4. **เลื่อนคำทุกคำ** ด้วยความเร็วของเลเวลปัจจุบัน
5. **ตรวจคำที่ตก** (y ≥ 600) ลบออก ลดหัวใจ ตั้ง `flashMs = 300` ถ้าคำที่ตกเป็นคำที่เล็งอยู่ ให้ยกเลิกการเล็ง
6. **ตรวจ Game Over** ถ้าหัวใจเป็น 0 เปลี่ยนเป็น GAME_OVER ล้าง `flashMs` เป็น 0 แล้ว **return ทันที** (ไม่เกิดคำใหม่)
7. **ตัวจับเวลาเกิดคำ** ลด `spawnTimerMs` ถ้า ≤ 0 ให้เรียก `trySpawn` แล้ว **บวก** interval เพิ่ม

### เทคนิคเล็ก ๆ ที่ควรสังเกต

**`spawnTimerMs += interval` (ไม่ใช่ `= interval`)**
สมมติเฟรมหนึ่งยาว 16.7 ms และตัวจับเวลาติดลบไป −10 ms ถ้าเขียน `= 2000` จะเสียเศษ 10 ms นั้นทิ้งไปทุกรอบ จังหวะเกิดคำจะค่อย ๆ ช้าลง ส่วน `+=` จะได้ 1990 ms ทำให้จังหวะเที่ยงตรงในระยะยาว

**dt cap 100 ms**
ถ้าเครื่องค้างไป 2 วินาที (เช่น garbage collection) โดยไม่มี cap คำจะวาร์ปลงมาทีเดียว 80 px ตัวจำกัดนี้ทำให้เกมแค่ "ช้าลง" แทนที่จะ "กระโดด"

**`skipNextDt`**
ตอนกด Enter เพื่อเล่นต่อหลังหยุดชั่วคราว timestamp ล่าสุดอาจเก่าไปหลายนาที ถ้าคำนวณ dt ตามปกติ คำจะกระโดด เกมจึงตั้ง flag ให้เฟรมแรกใช้ dt = 0 (และ `main.js` ก็รีเซ็ต `lastTimestamp` อีกชั้นเพื่อความชัวร์)

**การหยุดชั่วคราวทำง่ายมาก**
`update()` ตอน PAUSED แค่ `return state` เฉย ๆ ทุกอย่างทั้งตำแหน่งคำ เวลา ตัวจับเวลา จึงหยุดหมดโดยไม่ต้องเขียนโค้ดเพิ่ม นี่คือข้อดีของการเก็บตัวจับเวลาไว้ใน state

## 8. ระบบรับคีย์บอร์ดและการเล็งคำ

ทั้งหมดอยู่ใน `handleKey(state, key)` และ `handlePlayingKey` ใน [src/game-logic.js](src/game-logic.js)

### 8.1 แปลงปุ่มก่อน (`normalizeKey`)

- `'A'` → `'a'` (ไม่สนตัวพิมพ์ใหญ่-เล็ก)
- `'Enter'`, `'Backspace'`, `'Escape'` → คืนค่าเดิม
- อย่างอื่นทั้งหมด → `null` แล้วถูกเพิกเฉย

### 8.2 กติกาการเล็ง

**ยังไม่ได้เล็งคำไหน** แล้วพิมพ์ตัวอักษร L:
- หาคำที่ขึ้นต้นด้วย L ถ้ามีหลายคำ ให้เลือก **คำที่อยู่ต่ำที่สุด** (y มากที่สุด = อันตรายที่สุด) ถ้า y เท่ากัน เลือกคำที่ **เกิดก่อน** (id น้อยกว่า)
- ถ้าไม่มีคำไหนขึ้นต้นด้วย L → นับเป็นพิมพ์ผิด

**เล็งคำอยู่แล้ว** แล้วพิมพ์ตัวอักษร:
- ถ้าตรงกับตัวถัดไปของคำ → เพิ่มเข้า `typed` ถ้าครบทั้งคำ ยิงทิ้งทันทีและได้คะแนน
- ถ้าไม่ตรง → นับเป็นพิมพ์ผิด **และไม่ย้ายไปคำอื่น**

### 8.3 ตัวอย่าง: ทำไมต้อง "ล็อก" คำ

บนจอมี "cat" กับ "car" ผู้เล่นพิมพ์ `c` `a` เกมเล็ง "cat" (สมมติว่าอยู่ต่ำกว่า) แล้วผู้เล่นพิมพ์ `r`:

- **แบบที่เกมนี้เลือก:** `r` เป็นการพิมพ์ผิดของ "cat" เป้ายังเป็น "cat" อยู่
- **อีกแบบที่ไม่เลือก:** เปลี่ยนไปเล็ง "car" อัตโนมัติ

แบบล็อกทำให้ผู้เล่นรู้แน่ชัดเสมอว่ากำลังพิมพ์คำไหน ถ้าอยากเปลี่ยนคำต้องกด `Escape` หรือกด `Backspace` จนลบหมดเอง กฎข้อนี้เป็นการตัดสินใจของมนุษย์ (ดู PRD Changelog Revision 2)

และเพื่อไม่ให้เกิดความกำกวม **คำใหม่จะไม่ขึ้นต้นด้วยตัวอักษรเดียวกับคำที่เล็งอยู่**

## 9. การวาดภาพและการย่อให้พอดีหน้าต่าง

### 9.1 ผังของ canvas

ทุกอย่างถูกวาดในพิกัด "logical" ขนาด 800 × 680 เสมอ ไม่ว่าหน้าต่างจะใหญ่หรือเล็กแค่ไหน:

```
y = 0   ┌─────────────────────────────────────┐
        │ Score: 120   Lives: 3   Level: 2    │ ← แถบ HUD 40 px
y = 40  ├─────────────────────────────────────┤
        │ (เว้นว่าง 28 px ให้คำที่เพิ่งเกิดมองเห็นได้เต็มตัว)   │
y = 68  ├───────────── สนามเล่น y = 0 ──────────┤
        │        cat                          │
        │                  planet             │ ← สนามเล่น 600 px
        │    tree                             │
y = 668 ├───────────── เส้นพื้น y = 600 ────────┤
        │ (เว้นว่าง 12 px ให้หางตัวอักษร เช่น g, y)        │
y = 680 └─────────────────────────────────────┘
```

ทำไมต้องเว้น 28 px ด้านบน? เพราะตำแหน่ง y ของคำคือ **เส้นฐาน (baseline)** ของตัวอักษร คำที่เพิ่งเกิดที่ y = 0 ตัวอักษรจะอยู่เหนือเส้นนั้น ถ้าไม่เว้นที่ไว้ คำจะถูกตัดหายไปครึ่งตัว

### 9.2 ย่อให้พอดีหน้าต่าง (CSS)

```css
#game {
  width:  min(100vw, calc(100vh * 800 / 680));
  height: min(100vh, calc(100vw * 680 / 800));
  flex: none;
  margin: auto;
}
```

แปลว่า: "ให้ canvas ใหญ่ที่สุดเท่าที่จะใส่ในหน้าต่างได้ โดยคงสัดส่วน 800:680" หน้าต่างเล็กเกม **ย่อลง** ทั้งก้อน ไม่มีส่วนไหนถูกตัด ไม่มี scrollbar

| ขนาดหน้าต่าง | ขนาดเกมที่แสดง | ขนาดตัวอักษรของคำ |
|---|---|---|
| 1280 × 720 | 847 × 720 | 25.4 px |
| 667 × 567 | 667 × 567 | 20.0 px |
| 640 × 480 | 565 × 480 | 16.9 px |
| 320 × 240 | 282 × 240 | 8.5 px |

### 9.3 ให้ภาพคมทุกขนาด

CSS กำหนด "ขนาดที่แสดง" แต่ canvas ยังมี "ขนาดพิกเซลจริง" อีกค่า ถ้าสองค่านี้ไม่ตรงกัน ภาพจะเบลอ ฟังก์ชัน `ensureSize` ใน [src/renderer.js](src/renderer.js) จึงทำงานทุกเฟรม:

1. อ่านขนาดที่แสดงจริง (`clientWidth`, `clientHeight`) และ `devicePixelRatio` (จอ Retina = 2)
2. ถ้าค่าเปลี่ยน ตั้ง `canvas.width = clientWidth × dpr` (และความสูงเช่นกัน)
3. เรียก `ctx.setTransform(...)` ให้โค้ดวาดยังคิดเป็นพิกัด 800 × 680 ได้เหมือนเดิม

ผลคือ **game logic ไม่รู้เลยว่าหน้าต่างใหญ่แค่ไหน** คำตกด้วยความเร็วเท่าเดิมในทุกขนาดหน้าต่าง

| สิ่งที่วาด | สี |

### 10.4 เทคนิคน่าเรียนรู้ในเทส

- **ทดสอบที่ขอบเขตพอดี:** ตรวจเลเวลที่ 29.999 วินาที (ต้องเป็น 1) และ 30.000 วินาที (ต้องเป็น 2) เพราะบั๊กมักซ่อนอยู่ตรงรอยต่อ

## 12. บทเรียนที่ได้จากโปรเจกต์

### 12.1 บั๊กที่เทส 238 ข้อจับไม่ได้ (R-02)

โค้ดเดิมคำนวณความแม่นยำแบบนี้:

```js
Math.round((correct / total) * 100)      // ❌ หารก่อน
```

ลองกับ 23 ถูก 17 ผิด (รวม 40):

```
23 / 40       = 0.575   ← เลขฐานสองเก็บ 0.575 ไม่ได้ตรงเป๊ะ เก็บได้เป็น 0.57499999...
0.57499 * 100 = 57.4999...
Math.round    = 57       ← ผิด ควรได้ 58
```

แก้เป็น:

```js
Math.round((correct * 100) / total)      // ✅ คูณก่อน
// 2300 / 40 = 57.5 (เลขนี้เก็บได้ตรงเป๊ะ) → Math.round = 58
```

**ทำไมเทสเดิมไม่จับ?** เพราะกรณีทดสอบเดิม (เช่น 1/8 = 12.5%) บังเอิญเป็นเลขที่ฐานสองเก็บได้ตรง จึงผ่าน Reviewer เป็นคนเจอบั๊กนี้ จากนั้น QA เขียนเทสที่ fail ก่อน (test-first) แล้ว Developer จึงแก้

**บทเรียน:** เทสผ่านหมด ไม่ได้แปลว่าไม่มีบั๊ก การรีวิวโค้ดโดยคนที่สองยังจำเป็น และเวลาเลือกกรณีทดสอบเกี่ยวกับทศนิยม ต้องเลือกค่าที่ "ยาก" สำหรับเลขฐานสองด้วย

### 12.2 การแก้บั๊กหนึ่งทำให้เกิดบั๊กใหม่ (regression)

- **R-04:** ข้อความเบลอบนจอใหญ่ และตัวอักษรเล็กเกินไปในหน้าต่างเตี้ย → แก้โดยกำหนดขนาด canvas ขั้นต่ำ 667 × 567

- QA และ Reviewer จับได้ในรอบถัดไป มนุษย์ตัดสินใจว่า "การเห็นเกมครบทั้งจอ" สำคัญกว่า "ตัวอักษรต้องใหญ่ 20 px" แล้ว PO ปรับ PRD ตาม

**บทเรียน:** ข้อกำหนดสองข้ออาจขัดกันเอง (NFR-8 ตัวอักษรใหญ่พอ กับ AC-9.3 เห็นคำครบ) การเลือกว่าข้อไหนสำคัญกว่าเป็นหน้าที่ของคนที่ดูแลความต้องการ ไม่ใช่ของ Developer

เรียงจากง่ายไปยาก ทุกข้อให้รัน `npm test` หลังแก้ แล้วสังเกตว่าเทสไหนพังและเพราะอะไร

1. **ปรับความยาก:** เปลี่ยน `BASE_SPEED` ใน `CONFIG` จาก 40 เป็น 60 แล้วลองเล่น เทสไหนพังบ้าง? (ใบ้: เทสที่ตรวจว่าคำตกใน 15 วินาที)
2. **เพิ่มคำศัพท์:** เพิ่มคำใหม่ใน `src/words.js` แล้วลองใส่คำที่มีตัวพิมพ์ใหญ่หรือคำซ้ำ ดูว่า `words.test.js` จับได้อย่างไร
3. **อ่านเทสให้เข้าใจ:** เปิด `tests/spawn.test.js` หาเทสที่ใช้ `seqRng` แล้วอธิบายว่าแต่ละค่าในลิสต์ถูกใช้ทำอะไร (ความยาว? คำ? ตำแหน่ง x?)
4. **ทดลองทำให้บั๊กกลับมา:** เปลี่ยนสูตรความแม่นยำกลับเป็นแบบหารก่อน แล้วดูว่าเทสข้อไหน fail และค่าที่ได้คืออะไร
5. **ลองสลับลำดับใน `update()`:** ย้ายขั้นตอน "ตรวจ Game Over" ไปไว้หลัง "เกิดคำใหม่" แล้วดูว่าเทสไหนพัง และทำไมลำดับเดิมถึงถูก
6. **เพิ่มฟีเจอร์แบบทีม:** ลองเพิ่ม "คอมโบ" (ยิงติดกันโดยไม่พิมพ์ผิดได้คะแนนเพิ่ม) โดยทำตามขั้นตอนของทีม: เขียน AC ใน PRD ก่อน → ออกแบบใน DESIGN → เขียนเทสที่ fail → เขียนโค้ด → เทสผ่าน
7. **ใช้ agent เอง:** ถ้ามี Claude Code ลองสั่ง product-owner agent ให้เพิ่ม user story ใหม่ แล้วส่งต่อไปตาม pipeline ในหัวข้อ 11.2

## 15. อภิธานศัพท์

| คำ | ความหมาย |
|---|---|
| **PRD** (Product Requirements Document) | เอกสารบอกว่า "ต้องสร้างอะไร" จากมุมผู้ใช้ ไม่พูดถึงวิธีสร้าง |
| **User Story** | ความต้องการในรูป "ในฐานะผู้เล่น ฉันอยาก... เพื่อที่จะ..." |
| **Acceptance Criteria (AC)** | เงื่อนไขที่วัดผลได้ชัดเจน ว่างานแบบไหนถือว่า "เสร็จ" |
| **NFR** (Non-Functional Requirement) | ข้อกำหนดที่ไม่ใช่ฟีเจอร์ เช่น ความเร็ว การอ่านง่าย เบราว์เซอร์ที่รองรับ |
| **Pure function** | ฟังก์ชันที่ผลลัพธ์ขึ้นกับ input อย่างเดียว และไม่มีผลข้างเคียง |
| **Immutable** | ไม่แก้ข้อมูลเดิม สร้างก้อนใหม่แทน |
| **Dependency Injection** | ส่งสิ่งที่ฟังก์ชันต้องใช้ (เช่น rng) เข้าไปเป็นพารามิเตอร์ แทนให้ฟังก์ชันไปหาเอง |
| **dt** (delta time) | เวลาที่ผ่านไประหว่างเฟรมก่อนหน้ากับเฟรมนี้ |
| **requestAnimationFrame (rAF)** | API ของเบราว์เซอร์ที่เรียกฟังก์ชันของเราก่อนวาดจอแต่ละครั้ง |
| **State machine** | ระบบที่อยู่ได้ทีละสถานะ และเปลี่ยนสถานะตามเหตุการณ์ที่กำหนด |
| **Baseline** | เส้นฐานที่ตัวอักษร "นั่ง" อยู่ ส่วนหางของ g, y จะห้อยต่ำกว่าเส้นนี้ |
| **devicePixelRatio (DPR)** | จำนวนพิกเซลจริงต่อ 1 CSS pixel จอทั่วไป = 1, จอ Retina = 2 |
| **Logical coordinates** | พิกัดสมมติที่ใช้คิดในเกม (800 × 600) แยกจากขนาดที่แสดงจริงบนจอ |
| **Unit test** | เทสที่ตรวจฟังก์ชันทีละชิ้นโดยไม่ต้องรันทั้งระบบ |
| **Test-first** | เขียนเทสที่ fail ก่อน แล้วค่อยเขียนโค้ดให้ผ่าน |
| **Regression** | บั๊กใหม่ที่เกิดจากการแก้ไขส่วนอื่น |
| **Traceability** | การตามรอยได้ว่าโค้ดหรือเทสแต่ละชิ้นมาจากข้อกำหนดข้อไหน |
| **Subagent** | AI agent ที่ถูกเรียกใช้ให้ทำงานเฉพาะทาง มีบทบาทและข้อจำกัดของตัวเอง |
| **Timebox** | กำหนดเวลาสูงสุดให้งาน หมดเวลาแล้วหยุด ไม่วนไปเรื่อย ๆ |
